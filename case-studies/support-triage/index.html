Support and customer success

Giving support an answer before engineering gets paged

How a support team replaces 'it looks like a DNS thing' with a scored, shareable report attached to the ticket.

Try this on your domain Ask how it would fit

Illustrative scenario — a composite of how the API is designed to be used, not an account of a named customer.

The problem

Every deliverability complaint looks the same from the outside: mail is not arriving. Support has no way to tell a missing DKIM selector from a DMARC policy that quarantines the customer's own traffic, so everything escalates.

How the audit is wired in

  1. Fetch GET /v1/audit/{domain}/report.md and paste the markdown straight into the ticket — it renders in every helpdesk.
  2. Use ?format=html when the report goes to the customer instead of the queue.
  3. Compare the failing domain against a known-good one with POST /v1/compare to isolate the single differing check.
  4. Escalate only when the audit passes and mail still fails — that is a genuine engineering problem.

What changes

Tickets arrive at engineering with evidence attached, and most never arrive at all because the report told the customer what to change.

  • Markdown reports paste into any helpdesk
  • Side-by-side compare isolates the broken check
  • Cached repeat lookups do not re-hit DNS
