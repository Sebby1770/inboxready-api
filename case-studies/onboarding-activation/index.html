B2B SaaS onboarding

Cutting DNS back-and-forth out of self-serve activation

How a sender-facing SaaS turns a blocking DNS step into a guided, self-correcting part of its signup flow.

Try this on your domain Ask how it would fit

Illustrative scenario — a composite of how the API is designed to be used, not an account of a named customer.

The problem

Customers sign up, hit 'send from your own domain', and stall. The product shows a documentation link; the customer pastes records into the wrong zone; support inherits a ticket that is really a DNS question. Activation drags on for days and the account never reaches the aha moment.

How the audit is wired in

  1. Call POST /v1/audits/email-domain the moment the customer types their domain.
  2. Render the returned checks inline instead of linking to docs — each failing check already carries its own remediation string.
  3. Use detected providers to narrow the instructions to that registrar or ESP.
  4. Re-run the audit on a timer while the customer is still in the wizard, and unblock the step automatically once the score clears your threshold.

What changes

The DNS step becomes self-service. The customer sees exactly which record is missing, fixes it, and the wizard advances without a human touching it.

  • 7 checks run per activation attempt
  • 1 call replaces the documentation hand-off
  • <5 min typical integration effort

The call

Integration sketch

const audit = await fetch("/v1/audits/email-domain", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ domain })
}).then((r) => r.json());

if (audit.score >= 80) unlockSendingStep();
else showChecklist(audit.recommendations);
